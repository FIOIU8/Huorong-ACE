## 修复：原生 Win32 全屏红屏 + 按任意键/点击退出
- 用户反馈 Fyne 红屏缺陷：按钮无法关闭全屏窗口、红屏未覆盖全屏 → 改为原生 Win32 实现。
- 关键教训：`golang.org/x/sys/windows` v0.47.0 **不包含** GDI/USER32 API（HDC、RECT、PostMessage、GetModuleHandle、CreateSolidBrush 等均无），之前依赖它的符号名全部编译失败。
- 解决方案：彻底移除 x/sys/windows 依赖，`internal/ui/redscreen_windows.go`（`//go:build windows`）改用 Go 标准库 `syscall`（NewLazyDLL/NewProc、NewCallback、UTF16PtrFromString）手写全部 Win32 类型与函数声明（HWND/WNDCLASSEX/PAINTSTRUCT/LOGFONT/RECT 等，字段布局按 LLP64 对齐）。原 Fyne 版降为 `redscreen.go`（`//go:build !windows`）回退。
- 行为：CreateWindowEx 覆盖整个 VirtualScreen（含任务栏），WS_EX_TOPMOST；WM_KEYDOWN/WM_SYSKEYDOWN/WM_CHAR + 鼠标三键 → 关闭；自定义 msgRedClose/msgRedUpdate（WM_USER+1/+2）经 PostMessage 跨 goroutine 关闭窗口并退出消息循环。
- 修复的 Go 错误：`bb` 重复 `:=`、onPaint 未用变量 `w`、LOGFONT 字段名 `Height/Weight` → `LfHeight/LfWeight`。
- 重新编译通过（BUILD_EXIT=0，vet 0），产物 53MB。沙箱无显示器无法实跑 GUI，需用户在真实 Windows 验证“覆盖任务栏/任意键或点击退出”。

## 新增：启动/退出系统通知
- 需求：启动和关闭时给出提示（系统通知形式）。
- 关键决策：**不用 Fyne 的 `a.SendNotification`**。其 Windows 实现（`app/app_windows.go`）是拼 PowerShell 脚本再 `exec` 调 `ToastNotificationManager`，慢（起进程）、依赖未注册的 AUMID 可能静默失败，且退出时进程已结束、脚本根本来不及跑。
- 实现：`internal/ui/toast_windows.go`（`//go:build windows`）自绘原生通知卡片：
  - WS_POPUP + WS_EX_TOPMOST|TOOLWINDOW|COMPOSITED|**LAYERED**（0x00080000）；`CreateRoundRectRgn`+`SetWindowRgn` 做圆角；`SetLayeredWindowAttributes(LWA_ALPHA)` 做 0→255 淡入（goroutine sleep 步进，跨线程安全，无需 SetTimer）。
  - 位置用 `SystemParametersInfoW(SPI_GETWORKAREA=0x0030)` 取工作区，右下角留 16px，自动避开任务栏；380×96 深色卡片 #2B2B2B + #4A4A4A 边框 + 红色盾牌图标（Polygon）+ 标题/内容文字。
  - 4 秒自动消失，点击可提前关闭。
  - **单例设计**（`var toast = &toastWin{}`）：窗口类 WndProc 回调绑定单例方法，避免重复 RegisterClassEx 导致新窗口沿用旧对象回调（类比 RedScreen 也是单实例才安全）。
- 复用：toast 文件直接复用 redscreen_windows.go 的 HWND/RECT/MSG/WNDCLASSEX/PAINTSTRUCT/LOGFONT、createSolidBrush/fillRect/drawTextIn/rgb/roundRectFill/loadCursor/psSolid/wmUser 等（同包同 build tag）。新增符号：wsExLayered、dtLeft、dtWordBreak、pPolygon+polygon、pSystemParametersInfo/getWorkArea、pCreateRoundRectRgn、pSetWindowRgn、pSetLayeredWindowAttributes。
- `main.go`：启动后 `ui.Notify(a, "火绒ACE 已启动", ...)`；托盘「退出」改为 goroutine：`mon.Stop()` → Notify → sleep `exitNoticeDelay`(2500ms) → `a.Quit()`（否则通知随进程一起消失）。
- 跨平台回退：`internal/ui/toast.go`（`//go:build !windows`）用 Fyne `app.SendNotification(&fyne.Notification{Title, Content})`（已核对 v2.8.1 字段名）。
- 重编译通过（BUILD_EXIT=0，vet 0），产物 53MB。Linux 交叉 vet 仅因 fyne GL 依赖需 cgo 失败，与本次改动无关。

## 设置界面观感修复（用户发来真机截图）
用户截图指出实际效果仍不好看。定位到 6 个真实缺陷并逐个修掉：

1. **致命：字号整体偏小约 1/3。** `drawTextIn` 把 `px` 直接写进 `LOGFONT.LfHeight`，而 GDI 规定**正值 = 字符单元格高（含 internal leading），负值 = em 高**。所以传 14 实得约 10.5px 视觉大小。新增 `drawUIText`（`LfHeight = -px`）供设置窗口专用，避免改动红屏既有观感；EDIT 控件字体同步改为 `LfHeight = -14`。
2. **开关的圆形滑块画成了方块。** 原实现用 `FillRect` 填滑块——`FillRect` 只能画矩形。改为 `roundRectFill(kr, knob, knob, d/2)` 得到真正的圆。
3. **原生 EDIT 的 3D 凹陷边框与扁平设计冲突。** 去掉 `WS_EX_CLIENTEDGE`/`WS_BORDER`，改由父窗口先画圆角白底+描边（`drawField`），EDIT 内缩 3px 放在里面——内缩量必须大于圆角在角上的内凹量（r·(1−1/√2)≈0.29r），3px > 6px 半径的 1.76px，所以圆角弧不会被方形子窗口盖住。同时处理 `WM_CTLCOLOREDIT` 返回白色画刷，防止用户深色主题下 EDIT 底色变黑。
4. **输入框聚焦无反馈。** 新增 `EN_SETFOCUS`/`EN_KILLFOCUS`（0x0100/0x0200）记录 `focusEdit`，聚焦时描边转主题蓝。
5. **内容区顶部只有一行浮空的灰字。** 改为常驻「状态条」卡片：白底圆角 + 状态色圆点（绿=运行中 / 黄=测试模式 / 灰=已停止）+ 13px 正文，三页都显示，视觉重心一下就稳了。
6. **窗口底部大片空白。** 原 940×660 内容只到 y≈434。改为客户端定尺寸 **900×520**，并用 `AdjustWindowRectEx` 由客户端尺寸反算外框尺寸——之前手填窗口尺寸导致实际客户区比设计值小（有边框/标题栏），坐标全部偏移。

## 修复：检测不到火绒病毒处理 + 界面持续闪烁
用户反馈「一直闪」+「无法正常识别到火绒处理病毒的操作」。两条都是真 bug。

### A. 检测失效（根因：路径根本不存在）
- 实测 `C:/ProgramData/Huorong/Sysdiag/` 下**没有 log.db**。真实目录只有 applog.db / config.db / hips.db / **QuarantineEx.db** / Quarantine/ / db/ / log/。
- 用 Python sqlite3 逐个读表后确认真正的「病毒处理记录」在：
  **`C:/ProgramData/Huorong/Sysdiag/QuarantineEx.db` → 表 `FilesV3_60`**
  列：`id, fn, sha1, vn, fid, ts, rid, info, type`
  - `vn` = **病毒名**（实测 `Trojan/MEMZ.n`、`HEUR:TrojanDropper/BAT.Agent.a`）
  - `fn` = 完整文件路径
  - `ts` = Unix 时间戳；`type`=1
- **第二个坑：这个库是 WAL 模式且被火绒服务持有**，`mode=ro` 直连直接失败（`unable to open database file`），实测两条 DSN 都 FAIL。必须先把 `db`、`db-wal`、`db-shm` 复制到临时目录再打开副本（WAL 里才是最新数据，所以不能用 `immutable=1`）。
- 重写 `internal/monitor/logdb.go`：快照复制 → 开副本 → `rowid > lastID` 增量 → 关闭 → 删临时目录。表解析优先级 `FilesV3_60` → `FilesV3*` → `HrLogV3`/`HrLog` → 首个非 sqlite_sequence 表。
- **判定逻辑改为**：`vn` 非空即视为威胁（隔离库里只可能存被处理的威胁），关键词过滤只用于无 `vn` 的自定义库。理由：对隔离库跑关键词只会导致漏报（`Worm/Generic` 永远匹配不到「病毒/木马/Trojan」列表）。
- **去重**：火绒对同一文件会连写多行（实测 15 行只对应 2 个样本）。按 `vn` 做 key、15 秒窗口、map + 过期清理。选 15s 而非 60s 是为了让用户拿同一个样本重复测试时不用等太久。
- `config.go`：新增 `QuarantineDBPath()`（读 `ProgramData` 环境变量）；`legacyLogPath` 迁移——旧配置仍指向 log.db 且隔离库存在时自动切换并写回 config.json。
- 新增 `Monitor.Reload(path)`：设置里改路径/保存后立即重开数据库，不用重启。`pollOnce` 改为持锁取 `m.db` 快照，避免与 Reload 竞争。
- 测试 `internal/monitor/logdb_test.go`（无火绒时自动 skip）：实测输出 `Trojan/MEMZ.n` + 完整路径，PASS。

### B. 界面闪烁
- 主因：直接在窗口 DC 上逐条绘制 chrome，绘制过程可见 → 半帧闪烁。改为**双缓冲**：`CreateCompatibleDC` + `CreateCompatibleBitmap` → `m.paint(mem)` → 一次 `BitBlt(SRCCOPY)` → 还原并删除。原 `onPaint` 拆成「包装 + `paint(hdc,w,h)`」。
- 次因：layout 在每次重绘里跑，无条件 `MoveWindow`/`ShowWindow` 子 EDIT。`editState{rect, shown}` 同时记录几何与可见性，两者都变化时才操作（`ShowWindow` 无条件调用也会触发重绘）。
- 定时器每 1s 无条件整窗重绘 → `updateStatus()` 改为返回 bool，只在状态文本/等级/开关真的变化时才 `InvalidateRect`。

### 顺带修掉的崩溃 bug
`stringify` 里 `strconv.FormatInt(t, 64)` 应为 `10`——**进制传 64 会 panic**（`strconv: illegal AppendInt/FormatInt base`），轮询一遇到整数列（id/ts/type）整个监控就崩。是重写时手误，靠新写的测试当场抓到。

### 结果
`go build` + `go vet ./...` + `go test ./...` 全绿，Huorong-ACE.exe 53MB。

## 红屏改为「仅 继续按钮 / Esc 可关」+ 修复重复弹窗
用户两点要求：①红屏只能在点「继续」或按 Esc 时关闭；②历史记录 / 多条重复记载会一直弹窗，建议按日志时间判断。

### A. 红屏退出方式（internal/ui/redscreen_windows.go）
- 原来 `wmKeyDown|wmSysKeyDown|wmChar` 和三个鼠标键**一律关闭** → 改成：
  - `wmKeyDown|wmSysKeyDown`：只有 `wparam == vkEscape` 才关闭，其余按键直接吞掉（防误触关掉）。
  - `wmLButtonDown`：命中按钮矩形才关闭；点别处无效。
  - `wmRButtonDown|wmMButtonDown`：吞掉，不关闭。
- 按钮几何抽成 `redButtonRect(w,h)`，**绘制与命中测试共用同一个函数**，避免两处坐标漂移；结果缓存在 `r.btnRect`。
- 新增悬停反馈：`wmMouseMove` 计算 `btnHover`，只在变化时 `InvalidateRect`；`wmSetCursor` 命中时 `SetCursor(LoadCursor(0, IDC_HAND=32649))` 并返回 1，否则交给 DefWindowProc 显示类光标（箭头）。新增 `colBtnHover=#E47478`。
- 底部新增提示行 `hintText = "点击「继续」或按 Esc 退出"`（0.902~0.932，colInfo），否则用户不知道怎么退。
- 非 Windows 兜底 `redscreen.go` 同步加 `Canvas().SetOnTypedKey` 处理 Esc，行为对齐。

### B. 重复弹窗（internal/monitor/logdb.go）
根因是原来只有 rowid 游标 + 15 秒去重，历史记录和火绒的重复写入都挡不住。
- **新增时间游标 `startTS`**：`Open()` 时取 `SELECT MAX("ts")` 作为水位；`Poll()` 里 `ts <= startTS` 的行直接跳过，处理完把 `startTS` 推进到本轮最大 ts。这样启动前已存在的记录、以及同一事件的重复行（ts 相同或更旧）都不会再触发。
- 没有 `ts` 列的自定义库 → `maxTS` 返回 0，时间闸门自动失效，退回纯 rowid 游标。
- 去重窗口 15s → **3 分钟**（key 仍为 `vn`）。15s 挡不住「解压/反复扫描」这种跨秒的连续写入。
- 实测（logdb_test.go 三段断言，全过）：
  1. Open 后 Poll → 0 条（历史不弹）
  2. 只回退 rowid → 仍 0 条（证明时间游标真的生效）
  3. rowid+startTS 都回退 → 2 条，分别是 `HEUR:TrojanDropper/BAT.Agent.a` 和 `Trojan/MEMZ.n`，且同一威胁不重复（15 行历史 → 2 次告警）
- 设置页「使用说明」文案同步更新（退出方式 + 去重说明），说明卡片高度 250→290 容纳新增两段。

结果：`go build` + `go vet ./...` + `go test ./internal/monitor/` 全绿，Huorong-ACE.exe 53MB。

## Go → C# 重构（基线先存档，再整体重写）
- 存档：git commit `c67c7f0` + tag `go-baseline` + `backup/huorong-ace-go-baseline.zip`（64KB，git archive）。Go 源码保留在仓库中可对照回退。
- 结构：`src/HuorongAce.Core`（net8.0，配置/日志/火绒库读取/监控）、`src/HuorongAce.Native`（net8.0-windows，Win32+红屏+托盘+通知）、`src/HuorongAce.App`（net8.0-windows10.0.19041.0，WinUI 3 设置界面），另两个 xunit 测试项目。
- 并发：goroutine+chan → Task+CancellationTokenSource+PeriodicTimer；`runtime.LockOSThread()` 消息循环 → STA 线程 + NativeWindowHost；回调 → event。
- 关键教训（都会静默失败或运行时崩溃，务必记住）：
  1. **WinUI 自动生成 `Program.Main`**（`App.g.i.cs`，受 `#if !DISABLE_XAML_GENERATED_MAIN` 保护）→ 手写入口点必须定义 `DISABLE_XAML_GENERATED_MAIN`，否则 CS0101/CS0111。
  2. **WinUI 的 PRI 索引依赖 VS 的 MSBuild 任务**（`Microsoft.Build.AppxPackage.dll`、`Microsoft.Build.Packaging.Pri.Tasks.dll`），.NET SDK 和 NuGet 里都没有。解法：装 VS 生成工具（`--add Microsoft.VisualStudio.Workload.UniversalBuildTools`，**免管理员也能装到用户目录**），再通过 `src/Directory.Build.props` 设 `AppxMSBuildToolsPath`（读环境变量 `VS_BUILDTOOLS_PATH`）。
  3. **`LibraryImport` 源生成器拒绝封送** `WndClassEx`/`PaintStruct`/`NotifyIconData` → 全部用 `DllImport` + `CharSet.Unicode`。
  4. **`NOTIFYICONDATA` 的 cbSize 必须是 V1/V2/V3/V4 之一**（64 位下 296/816/948/976）。结构体只声明到 `szTip` 得 296（V1）；停在 `dwInfoFlags` 会得到 952，四个都不匹配 → `Shell_NotifyIcon` 静默返回 FALSE，托盘图标消失。已用测试钉死 296。
  5. **DLL 归属**：`GetModuleHandle` 在 **kernel32**、`Shell_NotifyIcon` 在 **shell32**，误写 user32 会抛 `EntryPointNotFoundException`（靠冒烟测试才发现）。
  6. WinUI `Application` 没有 `DispatcherQueue` 属性 → 构造时 `DispatcherQueue.GetForCurrentThread()` 存字段；托盘回调用它 `TryEnqueue`。
  7. `Application.Start(_ => { _ = new App(); })` 里 `_` 既是 lambda 参数又是弃元 → 类型报错，改静态字段持有 App 防 GC。
